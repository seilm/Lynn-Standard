# Lynn Standard — 배포 가이드

건축예산팀 실행파트 실행 편성 기준 변경 이력 관리 사이트입니다. Supabase(데이터베이스+로그인+파일저장)와 GitHub Pages(무료 정적 호스팅)를 사용합니다. 누구나 인터넷으로 접속해서 조회할 수 있고, **팀원·파트장** 역할이 부여된 계정만 등록·수정·승인 권한을 가집니다. 새로 가입한 계정은 기본적으로 **조회자**(읽기 전용)로 등록됩니다.

## 폴더 구성

```
lynn-web/
├── index.html        ← 페이지 진입점
├── css/style.css      ← 스타일
├── js/
│   ├── config.js      ← ⚠️ 배포 전 이 파일에 Supabase 프로젝트 정보를 채워야 함
│   └── app.js          ← 전체 앱 로직
├── sql/
│   ├── schema.sql      ← 데이터베이스 테이블·권한 설정 (먼저 실행)
│   └── storage.sql     ← 첨부파일 저장소 설정 (그다음 실행)
└── README.md            ← 이 파일
```

## 1단계 — Supabase 프로젝트 준비

1. [supabase.com](https://supabase.com)에서 새 프로젝트를 만듭니다 (이미 있다면 그대로 사용).
2. 왼쪽 메뉴 **SQL Editor**를 엽니다.
3. `sql/schema.sql` 파일 내용 전체를 복사해서 붙여넣고 **Run**을 눌러 실행합니다.
4. 이어서 `sql/storage.sql` 파일 내용 전체를 복사해서 붙여넣고 **Run**을 눌러 실행합니다.
5. 왼쪽 메뉴 **Authentication → Providers**에서 **Email**이 켜져 있는지 확인합니다 (기본적으로 켜져 있습니다).
   - 팀 내부용으로만 쓸 거라면 **Authentication → Providers → Email**에서 "Confirm email"을 꺼두면, 가입 즉시 로그인되어 더 간편합니다 (꺼지 않으면 가입 후 확인 메일의 링크를 눌러야 로그인할 수 있어요).

## 2단계 — 연결 정보 입력

1. Supabase 프로젝트의 **Project Settings → API** 페이지를 엽니다.
2. **Project URL**과 **anon public** 키를 복사합니다.
3. 이 프로젝트의 `js/config.js` 파일을 열어 아래처럼 채워 넣습니다.

```js
window.LYNN_CONFIG = {
  url: "https://xxxxxxxxxxxx.supabase.co",
  anonKey: "eyJhbGciOi..."
};
```

`anonKey`(anon public key)는 브라우저에 그대로 노출되어도 안전하도록 설계된 키입니다. 실제 접근 권한은 `schema.sql`에서 설정한 Row Level Security(행 단위 보안) 정책이 담당합니다.

## 3단계 — 첫 관리자(파트장) 계정 만들기

가입만으로는 모든 계정이 조회자로 시작하기 때문에, 최초 1명은 SQL로 직접 파트장 권한을 줘야 합니다.

1. 배포된(또는 로컬의) 사이트에 접속해서 **회원가입**으로 본인 계정을 하나 만듭니다.
2. Supabase **SQL Editor**에서 아래 쿼리를 실행합니다. `본인이메일` 부분만 가입한 이메일로 바꿔주세요.

```sql
update public.profiles
set role = '파트장'
where id = (select id from auth.users where email = '본인이메일@example.com');
```

3. 사이트를 새로고침하면 파트장 권한(등록·수정·승인·팀원 역할 관리)이 생깁니다.
4. 이후 다른 팀원들은 각자 회원가입만 하면 되고, 파트장이 **설정** 페이지에서 그들의 역할을 팀원/파트장으로 바꿔주면 됩니다.

(선택) 파트장 계정이 실수로 잠기는 것에 대비해 `is_admin` 플래그도 함께 둘 수 있습니다: `update public.profiles set is_admin = true where id = ...;` — `is_admin = true`인 계정은 앱 화면에는 별도로 드러나지 않지만 파트장과 동일한 관리 권한을 가집니다.

## 4단계 — GitHub Pages로 배포

1. GitHub에 새 저장소를 만들고, 이 `lynn-web` 폴더의 내용 전체(이 README 포함)를 푸시합니다.
   - `js/config.js`에 실제 anon key가 들어가는데, anon key는 공개되어도 안전한 키이므로 공개(public) 저장소에 올려도 괜찮습니다.
2. 저장소의 **Settings → Pages**로 이동합니다.
3. **Source**를 `Deploy from a branch`로, **Branch**를 `main`(또는 사용 중인 기본 브랜치) `/ (root)`로 설정하고 저장합니다.
4. 몇 분 뒤 `https://사용자명.github.io/저장소명/` 주소로 사이트가 열립니다.

## 로컬에서 먼저 확인해보기

배포 전에 로컬에서 미리 확인하려면, `lynn-web` 폴더에서 아무 정적 서버나 띄우면 됩니다. 예:

```bash
npx serve .
# 또는
python3 -m http.server 8080
```

그 다음 브라우저로 `http://localhost:8080` (또는 표시된 주소)에 접속합니다. `js/config.js`에 Supabase 정보가 채워져 있어야 로그인 화면이 정상적으로 나타납니다 — 채워지지 않았다면 "설정이 필요해요" 안내가 표시됩니다.

## 지침서 검색 (실행지침서 PDF)

상단바의 **✦ 지침서 검색**에서 공통가설·건축·현장관리비 실행지침서 PDF 내용을 바로 검색할 수 있습니다. 검색 결과를 누르면 원본 PDF 그 페이지가 그대로 열리고, 데스크톱에서는 마우스를 올려 돋보기로 확대해서 볼 수 있습니다(고해상도로 렌더링돼서 확대해도 또렷합니다).

- 처음에는 지침서가 비어있습니다. **파트장**이 **설정** 페이지 하단 "실행지침서 (PDF)"에서 공통가설/건축/현장관리비 3개 PDF를 각각 업로드해주세요.
- 업로드 흐름은 **업로드/교체(파일 선택) → 개정일 지정 → 저장** 순서입니다. 파일을 고르면 그 아래에 개정일 입력칸과 저장·취소 버튼이 나타나고, 개정일은 실제 지침서 문서에 적힌 개정일로 맞춘 뒤 저장을 눌러야 반영됩니다. 이 날짜가 "지침서 개정 기준선" 표시의 기준이 됩니다.
- 업로드하면 브라우저에서 자동으로 페이지별 텍스트를 추출해서 저장하기 때문에(서버나 별도 AI 키 불필요), 페이지가 많은 파일(수백 페이지)은 분석에 시간이 좀 걸릴 수 있습니다 — 완료될 때까지 창을 닫지 마세요.
- 지침서는 보통 반기에 한 번 개정됩니다. 개정판이 나오면 같은 방법으로 새 PDF를 올려주세요. 업로드할 때마다 이전 판이 사라지지 않고 **변경 이력**에 함께 남아서, 설정 페이지의 "변경 이력 (n건)"을 펼치면 그동안의 판(날짜·파일명·업로더)을 모두 확인할 수 있고, 잘못 올린 이력은 ✕ 버튼으로 삭제할 수 있습니다. (단, 이 변경 이력은 처음 도입된 버전 이후에 올린 판부터만 쌓입니다 — 그 이전에 올려둔 판은 최신 정보만 남아있고 이력에는 나타나지 않아요.)

## 지침서 개정 기준선

지침서가 개정될 때마다 이 사이트를 매번 다시 배포할 수는 없다 보니, 대신 "최신 지침서가 언제 개정됐는지"를 기준선으로 삼아 현장별 반영 여부를 보여주도록 했습니다.

- **변경 이력 목록**: 상단에 각 공종별 최신 지침서 개정일이 안내 배너로 표시됩니다.
- **현장현황**: 현장 상세 화면에 "이 현장에 적용된 지침서 시점"이 "공통가설 26.08.18 판 / 건축 26.09.21판 / 현장관리비 26.09.21판"처럼 한 줄로 표시됩니다. 공종별 드롭다운에서 업로드 이력 중 실제로 그 현장에 반영한 판을 직접 골라 기록할 수 있고, "현재 지침서 기준으로 한번에 기록" 버튼을 누르면 세 공종 모두 최신 판으로 한 번에 채워집니다. 이후 지침서가 다시 개정됐는데 현장이 예전 판을 기록하고 있으면 해당 공종 표시가 진한 색으로 강조됩니다.
- 현장 상세 화면 상단에서 그 현장의 **담당자**를 지정할 수 있습니다. 등록된 팀원 중에서 고르면 현장 목록에도 담당자 이름이 칩으로 표시됩니다.

## 이번 버전에서 빠진 기능

원래 Claude Artifact 버전에 있던 아래 기능은 이번 자체 호스팅 버전에서는 뺐습니다. 필요하면 나중에 추가로 요청해주세요.

- **팀원 추가 시 검색/일괄 추천**: 예전 버전은 Claude 플랫폼이 제공하는 "가입된 사용자 검색" 기능을 썼는데, Supabase에는 이런 공개 검색 API가 없습니다. 그래서 이번 버전은 "먼저 회원가입 → 설정 페이지에서 역할 변경" 흐름으로 바뀌었습니다 (위 3단계 참고).

## 조회자 승인 (대외비 조회 제한)

모든 기준이 대외비라서, 새로 가입한 **조회자**는 팀원 또는 파트장이 **설정** 페이지에서 "조회 승인" 버튼을 눌러주기 전까지는 변경 이력·지침서 등 실제 내용을 볼 수 없고, 승인 대기 화면만 보입니다. 팀원·파트장은 역할 자체로 항상 조회할 수 있어서 이 승인이 필요 없습니다. 조회 승인은 파트장뿐 아니라 팀원도 할 수 있습니다.

(참고) 첨부파일·지침서 PDF의 실제 파일 링크는 Supabase Storage 공개 버킷의 URL이라, 그 링크를 직접 아는 사람은 승인 여부와 무관하게 파일을 열어볼 수 있습니다. 이번 업데이트는 목록·검색·상세 화면(주소를 몰라도 보이는 경로)을 승인 여부로 가리는 것까지만 다룹니다 — 파일 링크 자체까지 막으려면(서명된 URL 방식) 구조를 더 크게 바꿔야 해서, 필요하면 별도로 요청해주세요.

## 이미 배포해서 쓰고 있었다면 (업데이트 반영 방법)

이번 업데이트로:
- `profiles` 테이블에 `view_approved` 컬럼이 추가되고, "조회자 승인" 기능이 생겼습니다 (위 섹션 참고). 이 컬럼이 추가되면 **기존에 등록되어 있던 조회자들도 전부 미승인 상태로 바뀌니**, 필요한 사람에게는 설정 페이지에서 다시 승인해주세요 (팀원·파트장 역할인 사람은 영향 없습니다).
- `changes`/`sites`/`guideline_docs`/`guideline_chunks`/`guideline_revisions` 테이블의 조회(select) 정책이 "누구나"에서 "팀원·파트장이거나 승인된 조회자만"으로 바뀌었습니다.
- `index.html`의 Supabase 클라이언트 버전을 최신으로 올렸습니다 — 최근 Supabase가 API 키 체계를 `sb_publishable_...` 형식으로 바꾸면서, 예전 버전의 클라이언트 라이브러리로는 로그인은 되는데 등록·수정·승인 같은 로그인 필요 작업만 조용히 실패하는 사례가 보고됐습니다.
- 사이트 파비콘(브라우저 탭 아이콘)이 추가됐습니다 (`img/` 폴더).
- **(중요) "PDF 업로드가 저장 중에서 멈추는" 진짜 원인을 찾아 고쳤습니다.** `index.html`에 화면 하단에 잠깐 뜨는 알림(토스트) 문구를 표시할 `<div id="toast">`가 애초에 빠져 있어서, 지침서 PDF 업로드를 시작하자마자 호출되는 `toast(...)` 함수가 그 자리에서 오류를 내며 멈춰버렸습니다(업로드 로직이 시작도 되기 전에 죽는 것). `index.html`에 그 div를 추가하고, `toast()` 함수도 대상 요소가 없으면 조용히 넘어가도록 방어 코드를 넣었습니다.
- **(중요) `sql/schema.sql`의 실행 순서 버그도 고쳤습니다.** 새로 추가됐던 `view_approved` 컬럼을 실제로 추가하는 `alter table` 문이, 그 컬럼을 참조하는 `can_view()` 함수보다 뒤에 있어서 — 이미 배포된 DB에 이 스크립트를 다시 실행하면 `column "view_approved" does not exist` 에러로 스크립트 전체가 중간에 멈춰버렸습니다. 이 때문에 스크립트 뒷부분에 있는 `guideline_docs`/`guideline_chunks`/`guideline_revisions` 테이블 생성 및 각종 RLS 정책 갱신이 전혀 반영되지 않았을 수 있습니다. `alter table` 문을 함수보다 앞으로 옮겨서 고쳤습니다 — **`sql/schema.sql` 전체를 다시 한 번 실행해주세요.**

처음 배포가 아니라 이미 쓰고 있던 사이트라면 아래를 해주세요.

1. Supabase **SQL Editor**에서 `sql/schema.sql`과 `sql/storage.sql`을 다시 전체 실행합니다 (이미 있는 테이블·정책은 건너뛰고 새로 추가된 것만 만들어지므로 다시 실행해도 안전합니다).
2. 기존에 "현관비"로 등록해둔 변경 이력이 있다면, 아래 SQL로 한 번에 이름을 바꿔주세요.

```sql
update public.changes set major = '현장관리비' where major = '현관비';
```

3. GitHub 저장소에 이번에 새로 받은 파일들(`index.html`, `css/style.css`, `js/app.js`, `img/` 폴더 전체)을 덮어써서 다시 올립니다.
4. 기존 조회자 중 계속 조회 권한을 줘야 하는 사람이 있다면, 설정 페이지에서 "조회 승인"을 다시 눌러주세요.

## 문제가 생기면

- 로그인 화면 대신 **"설정이 필요해요"**가 보인다 → `js/config.js`에 URL/키가 아직 기본값(`YOUR-PROJECT`)입니다.
- 가입은 되는데 **아무 데이터도 안 보인다** → 조회 승인을 안 받은 조회자라면 정상입니다(위 "조회자 승인" 섹션 참고). 팀원·파트장인데도 안 보인다면 `sql/schema.sql`을 실행하지 않았거나 일부만 실행됐을 수 있습니다. SQL Editor에서 다시 전체 실행해보세요.
- 파일 첨부가 안 된다 → `sql/storage.sql`을 실행했는지 확인하세요.
- **PDF 업로드가 "저장 중"에서 멈춘다** → `index.html`의 토스트(`#toast`) 누락 버그가 원인이었습니다. 최신 `index.html`·`js/app.js`로 교체하면 해결됩니다.
